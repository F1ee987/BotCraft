# BotCraft

AI 机器人搭建平台 —— **单文件**前端 SPA，在浏览器内可视化创建、测试、编排与发布机器人工作流。全部 UI、样式与逻辑内嵌于 `BotCraft.html`（约 989 KB，零构建、零依赖），双击即可运行，也适合静态托管分发；另提供桌面版 `BotCraft.exe`（pywebview 打包，双击即开、无需浏览器）。

---

## 主要特性

**搭建与编排**
- 单文件应用：HTML/CSS/JS 全部内嵌，`BotCraft.html` 一个文件带走即用。
- 多机器人管理：内置 8 个示例机器人 + 自定义机器人；支持从模板一键创建副本、批量管理（勾选后批量复制 / 发布 / 删除）。
- 串行工作流引擎：可视化节点式流程，每个节点独立角色（开始 / 意图识别 / 检索 / 撰写 / 审核 / 去 AI 腔 / 人工审核），独立调用模型、上一步输出自动注入下一步；支持**流式逐字输出**与实时进度显示。
- 每个机器人专属编排：内置与模板机器人各配专属工作流（`ORCH_BY_NAME`），创建/复制时自动套用，加载时按名称兜底，避免共享引用污染。
- 知识库 TF-IDF 检索：自动切块、向量化、余弦相似度召回 Top-5，按节点角色智能注入上下文。
  - **来源可回溯**：回答下方出现「📚 参考来源 · 命中 N 处」，点开可看每条命中的**文档名 / 段落号 / 相关度 / 原文片段**——不再是「AI 说了个数字但你无从核对」。快照只存「文档 id + 段号 + 相关度 + 40 字摘要」，不把整篇文档复制进消息，历史记录不会被撑爆。
  - **文档闭环管理**：重命名 / 编辑 / 删除齐全，删除前先提示影响面；**内置文档受保护**（应用升级时可能被覆盖，因此不允许直接改），点编辑会改为「另存一份可自由编辑的副本」。
  - **网址导入**：直接抓取网页正文入库（含 HTML 转正文）；部分站点禁止跨域抓取，此时会引导你**粘贴正文**同样完成导入。
  - 内置 8 份演示文档（常见问题 FAQ / 产品使用手册 / 团队介绍 / 术语表 / 产品说明书 v3 / 售后与退换货政策 / 物流与配送说明 / 会员与优惠规则），开箱即有可检索的内容（示例「智能客服助手」已挂载其中两份），可随时删。
- 长期记忆：对话后自动提炼写入左侧「记忆」面板，**不仅记用户事实，也沉淀 AI 回复里用户未反对的结论/方案/建议/约定，以及用户询问的技术主题 / 代码用法 / 工具配置（记为「术语 / 方案」）**；记忆类型涵盖 偏好 / 事实 / 身份 / 项目 / 禁忌 / 术语 / 约定 / 结论 / 方案 / 建议 / 其他。
  - **双层注入**：禁忌 / 身份 / 约定 作为「常驻记忆」每轮必注入（换话题也不会丢），其余按「相关度 × 重要度」挑选最多 12 条，避免无关记忆挤占上下文。
  - **重要度模型**：类型权重 + 被注入使用频次 + 新近度 + 来源（手动添加加权）动态打分，驱动排序与淘汰；容量 60 条，超限时淘汰低分条目，**常驻类型受保护**（不再像旧版那样按时间砍掉最早的记忆）。
  - **语义去重**：字面归一化之外，再用「token 覆盖率」判据合并同义改写（如「用户偏好简洁回答」并入「用户偏好简洁回答，不要长篇大论」），同时不会误合并「喜欢猫 / 喜欢狗」这类一词之差的关键事实；类型互斥的条目不合并。
  - **过期修正**：AI 提炼时可用 `drop` 字段指明被新信息取代的旧记忆，系统据此删除旧条目，而不是让新旧矛盾信息并排堆积。
  - **面板管理**：搜索、类型筛选、三种排序（重要度 / 最新 / 常用）、📌 常驻标记、使用次数徽标、语义重复提示、「🧹 去重合并」「⬇️ 导出 / ⬆️ 导入」。
  - **兜底**：配置 Key 时由 AI 提炼，无 Key 时本地规则自动抽取（「我叫 XX」/「我不用 X」/「记住：…」/ 邮箱 / 手机 / #话题 等），本地抽取历史回扫已修正长对话后失效的问题。

**对话体验**
- ⚡ 快速模式：聊天框输入栏正上方一键开关。开启后，编排型机器人也只走**一次直接对话**（跳过串行分步工作流），首字更快、整答更跟手；仍会把编排节点的人设 / 流程设定合并进 system 提示，不退化成普通助手；需要多步推理时关闭即可恢复逐步编排。
- 🗂 多会话管理：同一机器人下可建多个会话并行推进不同话题（`🗂 会话` 面板新建 / 切换 / 重命名 / 删除），面板内支持**历史全文搜索**，直接跳到某句旧话所在的会话；对比两个方案、留一条干净的演示会话都不必再互相污染。
- 🔁 消息操作：AI 回复下方可**重新生成**（连同该条一起截断后重跑，保留之前历史），用户消息可**编辑重发**（改完从该处重新走一遍）。三条入口（发送 / 重新生成 / 编辑重发）共用同一条执行路径，工作流、生图、插件与错误处理行为完全一致。
- 📤 导出 Markdown：工具条一键把当前对话导出为 `.md` 文件（含角色标题与正文），便于归档、贴进文档或交给别人复核。
- ✦ 提示词库 + 斜杠指令：内置 10 条常用指令（总结 / 翻译 / 表格 / 润色 / 精简 / 扩写 / 步骤 / 挑错 / 邮件 / 代码），可自定义增删改，输入框点 `✦` 打开管理；**同一份清单在输入框打 `/` 时即时唤起**（↑↓ 选择、Enter 插入、Esc 关闭后可恢复），插入时连同 `/命令` 前缀一起替换，不会残留半截命令名。仅在行首或空格后触发，`10/100` 这类正常文本不会误弹菜单。
- 多模态输入：支持在聊天中发送图片 / 视频 / 音频；图片自动压缩至最长边 1280px、音频转 WAV 直传；若所选模型非视觉模型会给出提示（不阻断发送）。
- 长对话稳定：带上下文预算裁剪（历史 / 系统 / 知识库分别设上限）与请求自动重试（仅瞬态网络 / 408 / 429 / 5xx 重试，4xx 不重试），避免多轮对话后上下文超限或偶发网络错误导致的「调用失败」。预算超限时**用压缩代替截断丢弃** —— 详见下方 [上下文管理](#上下文管理)。
- Markdown 富文本：标题 / 列表 / 任务列表 / 表格 / 引用 / 代码块（带语言标签 + 单独复制按钮）/ 行内码，链接做了 XSS 过滤。围栏识别对输入很宽容：`objective-c` / `c++` / `c#` / `docker-compose` 这类带 `- + # /` 的语言名、Windows 粘贴带进来的 CRLF 换行、围栏行尾多余空格、末尾没闭合的围栏，都能正常渲染成代码块。
- 输入自适应：**所有要写正文的多行输入框**高度都随内容增减（写完变高、删掉缩回），到各自上限才转为内部滚动，不必手动拖右下角 —— 聊天输入框 160px、编辑消息 420px、人设提示词 560px、提示词库指令 300px、批量输入 320px、品牌记忆 220px、机器人介绍 200px。Enter 发送、Shift+Enter 换行（聊天输入框）。各框 CSS 里的 `min-height`（人设 220 / 批量 140 / 编辑消息 132 / 聊天 44…）仍是设计下限，内容少时不会被压得比设计更矮。
- 文体模板：内置 10 种风格（小红书 / 知乎 / 新闻 / 学术 / 口语 / 幽默 / 官方 / 文艺 / 电商 / 公众号），可一键应用、预览、取消。
- 插件管理闭环：安装 → 启用 → 卸载，三个动作都有入口（插件卡片在「已启用 / 已安装」两态都带**卸载**按钮，详情弹窗里也有一个）。卸载会**级联清掉所有机器人上对它的启用**（不只是当前机器人），并顺带关掉它独占的联网检索开关 —— 否则同一个插件在别的机器人上会留下「已启用但已卸载」的幽灵状态，点进去只报错。
- 真实工具执行：联网检索（DuckDuckGo 即时答案，免 Key）、天气查询（open-meteo，免 Key）、日历提醒（到点 Toast）、代码执行器（沙盒试运行）、**文生图（无需插件开关，只要表达「生成/画一张 XX 图片」「文生图」等意图即自动调用；未配置 Key 时回退 pollinations.ai 免费图床，配置 imageBaseURL + imageAPIKey 后走 OpenAI Images 兼容接口；生成结果以 data URL 内嵌直接显示在聊天框、重载对话后仍可见；失败时聊天内红色提示并引导去「设置 → 🖼️ 文生图设置」配置稳定接口）**。
- 执行日志面板：右下角浮窗实时显示每个工作流节点的角色 / 输出 / 耗时；可拖动、**拖到屏幕边缘收成 46px 小条（贴左/右边缘垂直居中）**、原位展开；支持浅色「阳光模式」跟随主题。
- 🗂 批量任务队列（工作台 → 更多 ▾ → 批量）：把一批问题交给当前机器人**逐个**处理，每条独立调用、不共享上下文，实时显示进度与逐条结果，跑完可导出 CSV / JSON / Markdown。
  - **降级可见**：调用失败或未配置 API Key 时，该条会被明确标成**降级**（内容是演示回复、不是模型输出）并单独计数，不混进「成功」里；导出文件同样带这个标记。批量场景没人逐条核对，这里最容易出现「一片全绿、却没有一句是真模型说的」。开跑前若没配 Key 会先拦一次并说明后果。
  - **导入不乱码**：`.txt` / `.csv` 导入自动识别编码 —— 先按 UTF-8 解，出现无法解码的字节再回退 GBK（Excel 在中文 Windows 上「另存为 CSV」存的就是 GBK），并提示实际用的哪种。
  - **CSV 表头只跳一次**：导入时自动勾选「首行作为标题」，与复选框共用同一个开关；不会既跳过又再跳一次吃掉第一条数据。CSV 只按扩展名识别，含逗号的普通 txt 不会被当成表格切列。
  - **停止语义准确**：中途停止后没轮到的条目显示「已停止」而不是一直「排队」，进度停在真实完成数，结束时按「成功 / 降级 / 失败 / 未执行」分别报数。

**账号与数据**
- 本地登录：注册 / 登录 / 多账号，密码 PBKDF2-SHA256 本地哈希；顶栏头像下拉一键切换已认证账号（免重输密码）；登录失败有明确提示（密码错误红字等）；访客模式兜底保证进得去应用。
- 账号信息面板：顶栏头像 →「账号信息」，可改昵称、补填 / 修改邮箱、更换头像（配色 / 图案 / 上传图片）、**修改密码**；底部给出该账号的**数据概览**（机器人 / 知识库 / 收藏数量与本地占用空间）。
- 跨源备份迁移：导出 / 导入全部配置（机器人 / 知识库 / 收藏 / 设置），解决 file:// 与 localhost 源隔离导致数据互不可见的问题。
- 数据安全：桌面版**每次写盘前自动滚动备份**、备份列表一键回滚、存储占用按 key 排行并标出预警、**可清理的内联媒体一键剥除**、**应急恢复（彻底重置）** —— 详见下方 [数据安全](#数据安全) 章节。

**数据统计**
- Token 用量与费用：「数据分析」页展示调用次数、输入 / 输出 Token、按天与按模型的用量构成，以及**累计 / 今日费用估算**。
  - 数据源是 API 响应里的 `usage` 字段（**真实采集**）；服务端未回传时按字符数估算并打 `est` 标记，界面明确区分两者，**绝不把估算混进实测**。
  - 费用按内置参考单价表（元 / 百万 token，覆盖 GPT / DeepSeek / 通义 / 智谱 / Moonshot / Claude / Gemini 等）加权估算，带日期后缀的模型名走前缀匹配。**这是量级参考，不是账单金额。**
  - 按天聚合只保留最近 60 天，避免长期使用后把存储撑爆。
  - 面板右上角**「🗑 清空用量统计」**可把累计计数归零（换模型 / 换计费周期后重新观察用），需二次确认；只清用量，不动机器人 / 会话 / 知识库。

**发布与嵌入**
- 发布渠道：网页嵌入（生成 `<iframe>` + 独立嵌入页，带 `?botcfg=` 深链）、API 接口（拼好 system 提示词的 fetch / cURL 片段）、飞书 / 微信公众号 / 企业微信（Webhook / 回调地址）。
- 模板广场：把本地机器人发布成可复用模板，按名称去重、与内置模板混排。

**界面与适配**
- **全局液态玻璃 UI**：全局毛玻璃材质（结构面用 `backdrop-filter`，高频列表项用「半透明 + 边缘高光」模拟以保证 WebView2 帧率），顶栏 / 侧栏 / 内容区收口为同族**悬浮圆角玻璃珠**（不再是与侧栏割裂的整块平面）；背景是**双层异色反向流动的极光光晕**（第一层紫 / 靛 / 青绿 26s、第二层青 / 粉 / 橙 38s 反向慢流，错速叠加出液体感），玻璃必须有东西透出来才成立——这层光晕就是它的底；玻璃表面的顶缘高光 / 底缘暗线 / 外悬浮阴影构成「厚度」。流动只动 `transform`，走 GPU 合成、不触发重排重绘，并遵循 `prefers-reduced-motion`。对齐 iOS / macOS 系统语义色、SF Pro / 苹方字体栈、连续大圆角、iOS 分段控件与 51×31 开关、iMessage 式消息气泡。深 / 浅主题切换（日志面板等内联样式用 CSS 变量实时跟随）。
- **主题色与 app 图标统一为品牌紫**：主色 `#8b5cf6`（violet-500，浅色主题 `#7c3aed`），与 `botcraft.ico` 的靛紫渐变 `#6366f1 → #8b5cf6` 同源；主题色只在一处定义（`--brand` / `--brand-hi` / `--brand2`），所有按钮、气泡、选中态、图表与焦点描边自动跟随。记忆类型标签、模板头像等**功能分类色板**刻意保留多色，以便互相区分。
- **视觉与可访问性（2026-09 打磨一轮）**：
  - **对比度全量达标**：脚本按 WCAG 逐条实测全站 **565 组**「文字 × 背景」配对（半透明玻璃面会先合成到底色再算），**0 组低于门槛**。此前浅色主题是重灾区——次要文字 3.37:1、10 个记忆类型徽标 1.14–2.52:1、主色小字压玻璃 3.45:1 等，合计 **220 组**不达标。
  - **主色拆成两支**：`--brand-fill`（填充面，上面压白字）与 `--brand-text`（文字面，压在玻璃上）分开取值 —— 同一个紫不可能同时满足这两种用途；另加 `--brand-tint / -tint-2 / -line / -glow` 四档浓度令牌覆盖「淡底 / 高亮 / 描边 / 辉光」，组件里不再抄颜色副本，**换品牌色只动一处**。
  - **字体分层**：展示字走系统衬线栈，只用在页面大标题与 logo（中文小字号衬线在 Windows 会退化成宋体、观感像 Word，故刻意不下铺）；等宽字**内嵌** Source Code Pro（离线 exe 不能用外链字体）；数字统一按等宽渲染，统计卡 / 用量 / 版本号刷新时不再左右跳动。
  - **氛围与动效**：叠了一层 4% 透明度噪点，消掉大面积渐变的「数码带状感」；首屏改为错峰入场（顶栏淡入 → 侧栏滑入 → 标题 / 工具栏 / 卡片依次升起）；主按钮与机器人卡悬停多一道玻璃反光扫过，侧栏项悬停有左侧指示条滑入。全部遵循 `prefers-reduced-motion` 降级。
  - **点击目标**：主题切换球与 emoji 选择器补到 **44×44**（视觉尺寸不变，靠透明热区扩展）。
  - **设计系统令牌化**：颜色、字阶、间距、圆角、动效时长都有具名阶梯。此前 138 个令牌里，字阶 12 / 间距 7 / 动效 4 个的 `var()` **引用次数是 0** —— 定义了却没接上组件。本轮把**动效时长（109 处）、圆角（162 处）、间距 gap（112 处）** 从字面量收敛为令牌：圆角 8 档（4/6/8/10/12/16/20/999px）、间距 8 档（2/4/6/8/10/12/16/24px）、动效 7 档（120–640ms）。阶梯由**现有实际用值**归纳而来（不是另造一套），因此视觉漂移控制在 ±2px 内，另有 21 处圆角是纯写法归一（`980px`/`999px`/`31px` 三种胶囊写法统一）。此后调一条圆角/间距只需改一处。
- 侧边栏可收展，折叠态悬停图标显示名称 tooltip。
- **页面标题栏吸顶**：内容区（首页 / 模板 / 文体 / 知识库 / 收藏 / 数据分析）滚动时，页面标题与右侧那排操作按钮**浮在内容之上不再滚走**，长列表里也能随时点「导入文档 / 清除风格 / 搜索」；滚回顶部自动落回。未滚动时它完全透明、连边框都不留，静止页面与从前一模一样；滚动后才浮起玻璃底、对角高光与外悬浮阴影（沿用全局液态玻璃那套材质）。批量操作条会自动避让到标题栏下沿，两条吸顶不会叠在一起。桌面版窗口任意宽度都成立（窄屏标题换行时高度自动重算）。
- 命令面板（Ctrl / Cmd + K）、机器人切换下拉（搜索 + 头像 + 已发布徽标）。
- 移动端适配（≤760px 汉堡菜单 + 单列布局），嵌入模式（`?botcfg=`）只显示聊天区。
- 桌面图标 `botcraft.ico`（靛紫渐变 + 极简机器人头，16→256px 共 7 档，小尺寸单独绘制），并提供 `.url` 快捷方式入口。
- **界面品牌标记与图标同源**：顶栏与登录页左上角那枚标记（原来只是个几何白圆环）已换成与图标同一张机器人脸，由 `gen_icon.py` 内联注入 SVG。底色渐变走 `--brand-hi`/`--brand` 主题变量，深浅主题自动跟随；线宽按界面实际 28px 重算（主版天线等比缩到 28px 只有 0.9px，会被抗锯齿摊成灰雾）。

**模型接入**
- 支持 OpenAI、阿里云百炼、腾讯混元、智谱等多家提供商与自定义 baseURL；支持流式（SSE）与非流式调用；浏览器直连或用后端代理转发以隐藏 Key。

## 上下文管理

单次请求的上下文由 10 个来源拼成。过去这一块是黑箱：整体超预算时**按拼接顺序砍尾**，
而尾部恰好是「工作流设定 → 品牌档案 → 固定收尾」—— 于是知识库原样留着，
**品牌调性与流程约束却先被静默丢弃**（越重要的越先掉），用户看不到任何提示。

现在改为**按来源分区块记账 + 优先级装箱**：

| 优先级 | 区块 | 超预算时的行为 |
|---|---|---|
| 保护区（prio 0） | 人设提示词、品牌档案、固定收尾 | **永不裁剪**，预算再紧也完整保留 |
| 重要（prio 1） | 写作风格、插件说明、配图说明 | 后于可裁区被削减 |
| 普通（prio 2） | 工作流设定、长期记忆 | 可被整块丢弃 |
| 可裁（prio 3） | 工具结果、知识库 | **优先削减**（先截断，保留不下则整块丢弃） |

- **底部用量带**：实时显示 `🧩 上下文 N 字 · 系统 x/y（z%）· 历史 n 条 x/y`，
  发生裁剪时直接标出 `⚠️ 已裁剪 k 个区块`，点右侧「上下文详情 ›」看明细。
- **上下文详情面板**：逐区块列出字数、占预算比例、优先级与裁剪说明；
  **点击任意一行可展开实际送进模型的正文**，用来核对「到底发了什么出去」。
- **预览零副作用**：界面刷新时的用量预演不累加记忆使用次数、不写盘，
  不会污染记忆的重要度模型（连续预演的数值保持稳定）。
- 预算常量：系统提示 **20000 字**、历史对话 **60000 字**，见 `BotCraft.html` 的
  `SYS_BUDGET` / `HISTORY_BUDGET`。

### 超限自动压缩（压缩代替截断）

装箱只能决定「保谁、丢谁」，被丢掉的区块信息就真的没了。现在超预算的区块会先被
**压缩成要点摘要**再注入：

- **什么时候压**：区块分到的配额装不下它的原文，且「原长 ÷ 配额 ≥ 1.6」时才压 ——
  差距不大的让它按原样装进预算，不为此多发一次请求。
- **压到什么程度**：目标长度就是该区块的配额；压完仍超时，再截断**压缩版**
  （压缩版被截断也比原文被截断信息密度高）。
- **谁来压**：配置了 Key 时由模型压缩（提示词强制保留数字 / 专有名词 / 术语 / 明确要求与限制 /
  禁止项 / 步骤顺序，删除客套与重复，保持分点结构，只输出正文）；无 Key 或调用失败时回退到
  **本地规则压缩** —— 去空行、去装饰线、去重复行、合并空白，再按信息量挑行
  （列表项 / 标题 / 含「必须、不要、禁止」等约束信号的短行优先），且保持原顺序输出。零成本、同步、可预期。
- **只压一次**：压缩结果按「原文哈希 + 目标长度分桶」缓存，随机器人配置写进 `data.json`，
  同一份内容跨会话复用；缓存上限 24 条 / 40000 字，超出按最旧淘汰。**纯界面刷新不会触发压缩。**
- **失败安全**：预压缩在发送前异步进行，任何异常或单块超时（8 秒）都只是「这轮不压缩」，
  自动回退到原有截断逻辑，**绝不阻断发送**。
- **可关闭**：底部工具条的「🗜 超限压缩」开关（默认开）。关闭后完全回到旧的截断行为，不产生任何额外调用。
- **压缩 ≠ 裁剪**：用量带与面板把两者分开呈现 —— 压缩用正常色标
  `🗜 已压缩 k 个区块（省 N 字）`（信息密度提升，是改善），裁剪才用警示色 `⚠️ 已裁剪 k 个区块`（真的丢了内容）。
- 上下文面板顶部提供「🗜 立即压缩」按钮，可手动触发一次。

> 压缩是**按需**发生的：只有区块确实超出配额才压，且结果带缓存，同一份内容只压一次。
> 这与长期记忆的「对话后每 20 秒自动提炼」不同 —— 后者的调用频率跟随对话活跃度。

## 数据安全

桌面版的数据全部落在 `%APPDATA%\BotCraft\data.json` —— **一个文件**装着所有机器人、会话、知识库、记忆与账号。它坏了就是全没了，所以「自动备份 + 一键回滚 + 容量预警」是必需项，不是附加项。

### 读不出来 / 存不进去，都会明确告诉你

数据安全最怕的不是「坏」，而是**坏了却没人知道**。所以这里是刻意做的「反静默」设计，三条都针对同一类缺陷：不崩、不报错、界面一切正常，只是结果悄悄不能信。

- **读不出来时绝不写盘覆盖**。数据 JSON 解析失败（上次写入被截断、手工改坏）或结构不对时，程序**不会**退回演示数据再照常保存 —— 原来正是这条路径，会让用户什么都没做就丢掉全部机器人与聊天记录。现在的做法：先把**原始损坏内容**另存一份（`localStorage` 的 `bc.datarecover.<账号>`）→ 明确提示 → **不写盘**。若连备份都写不进去（配额已满），则挂起自动保存：宁可不存，也不覆盖你原来的数据。
- **单条记录坏掉只丢这一条**。归一化逐条兜住异常 —— 原来是 `.map` 整体抛错，于是一条坏数据连坐整个数组，全部机器人一起消失。
- **存不进去时明确报错**。`localStorage` 配额满会让写入抛异常，原来被 `catch {}` 吞掉：改了半天配置、聊了几十条，界面一切正常，一刷新全没了。现在会明确提示「本次改动没有写入磁盘」，并指向「设置 → 数据」导出备份、清理空间。

另外，**所有文本导入通道（知识库 / 数据集 / 模板 / 记忆 / 工作流 / 整机配置）都做了编码嗅探**：先按 UTF-8 解，出现替换字符 `U+FFFD` 才回退 GBK。中文 Windows 上 Excel「另存为 CSV」默认存的就是 GBK —— 此前导进来是满屏乱码，还会**原样送进模型**。

### 自动备份（防损坏 / 防误删）

- **备份的是「即将被覆盖的那一份」**：在写盘**之前**先拍快照，再原子替换。所以误删机器人之后保存，拿到的是**删除前**的状态 —— 而不是删完之后的。
- **限频 10 分钟**：一次会话可能触发几十次写盘，不设间隔会把备份目录瞬间灌满、反把有价值的旧快照挤出滚动窗口。
- **滚动保留最近 12 份**，落在 `%APPDATA%\BotCraft\backups\data-YYYYMMDD-HHMMSS.json`（文件名即拍摄时刻，便于肉眼定位）。
- **写盘用「临时文件 + 原子替换」**：强杀进程也不会留下半截 JSON。
- **备份失败只吞异常**：绝不让备份成为写盘的故障点 —— 备份不成也要先把用户数据存下来。

### 一键回滚

「💾 备份」面板列出全部备份，可**恢复 / 删除 / 立即备份**。

- 回滚前先把**当前状态**存一份（名字带 `pre-restore`），点错也能退回来。
- 恢复后页面自动重载并读入备份内容。
- 文件名做**路径穿越校验**：只接受 `data-*.json` 形式的纯文件名（不含任何目录分隔符），杜绝构造名字去读别的文件。

### 存储容量预警与一键瘦身

同一面板按 key 列出占用排行，并把机器人数据拆成「**内联媒体 / 正文 / 其它**」三类：

- 语音与图片是以 **base64 直接内嵌在消息里**的，只看总体积根本看不出瓶颈在哪 —— 实测一条几十秒的语音就能占掉整个数据文件的**一半以上**。
- 超过 4 MB 标红、占比过半标黄，一眼就知道该清哪一块。
- 统计口径同时扫**结构化媒体字段**（`audio / image / images / video / videos / files / attachments`）和**正文里内嵌的 `data:` 配图** —— 后者（AI 生图、粘贴的截图）曾因为只按字段名找而整片漏算，出现「面板说媒体 0 KB、文件却 500 KB」的矛盾。

诊断之后能直接治：面板下半部「🧹 可清理的内联媒体」按**可释放量降序**列出含媒体的会话，逐条「清理」或一键全清。

- **只清确实是内联媒体的东西**：字段值必须**以 `data:` 开头**才替换，正文里按 `data:<type>/<subtype>;base64,…` 精确匹配。媒体字段里存的也可能是外链 URL（`https://…`），那不是内联媒体，清掉等于把有用的东西删了。
- **只动媒体，不动别的**：原图 / 原音频换成文字占位「（内联媒体已清理）」，消息文字、角色、时间戳、会话标题全部保留 —— 对话脉络还在，只是看不到图了。
- **预估 = 实际**：可释放量不是另写一套遍历累加出来的，而是**拿一份深拷贝真清一遍、取差值**。统计与清理各维护一份规则早晚会分叉，出现「预计释放 300 KB、实际只掉 200 KB」这种自相矛盾（清不干净通常是漏了某种承载媒体，而漏在哪只有跑一遍才知道）。代价是一次深拷贝，点一次面板的量级可忽略。
- **一键全清只写一次盘**：先把所有目标会话清完，再统一 `saveBots()`；逐个会话各存一次会让滚动备份被同一批操作刷掉好几份。
- 面板列表用**下标**定位目标（`trimOneAsk(i)`），不把 bot / session 的 id 拼进内联 `onclick` —— id 要穿过 HTML 属性与 JS 字符串两层上下文，拼串既容易出错又平白多一个注入面；下标是刚渲染出来的、排序稳定，且越界时会提示「这个会话已经不在了」而不是静默失败。
- 清理**不可撤销**，因此两个入口都需二次确认，并在确认框里写明影响面与预估释放量。

### 应急恢复（彻底重置）

为「数据损坏导致打不开 / 一直卡在登录页」准备的最后一招：清空本机全部 BotCraft 数据、回到初始状态。桌面版与浏览器版**走的是两条不同的路**：

- **桌面版交给宿主原子完成**（`bc_factory_reset`）：清内存数据 → 写盘 → **重写注入页**，三步做完才 `location.reload()`。原因是桌面版的数据是打包时**写死在 `%APPDATA%\BotCraft\BotCraft.html` 的 `<head>` 里的启动快照**，reload 读回的正是那份旧快照 —— 页面侧「清完再 reload」会被原样灌回来，表现成「点了应急恢复，数据全在」。这个坑先于按钮存在：功能本身没错，是**刷新这个动作在桌面版不成立**。
- **浏览器直开**则 `localStorage` 就是真存储，清掉再 reload 即可。
- 清空前自动留一份 `pre-emergency` 备份，翻车了还能从「本机自动备份」里捞回来。
- 两个分支都需**强确认**（列出会被清掉的东西），不做「点一下就没」的设计。

> ⚠️ 「导出全部配置」会包含**明文 API Key**，请勿外传。

> 💡 备份只在**桌面版**生效（浏览器版没有落盘通道，数据本就在 localStorage 里，导出 / 导入配置即可迁移）。

## 第三方插件（沙箱）

内置插件（网页搜索、图片生成、PDF 解析、天气查询、日历/提醒、代码执行器）是**写死在页面里的能力开关** —— 点「安装」只是往 localStorage 记个名字，代码本来就在这份 HTML 里。

第三方插件是另一回事：**代码真的从外部来**。所以整个设计只围绕一个问题——凭什么敢跑它。

### 防线

唯一一道防线是 iframe 的 `sandbox` 属性，且**绝不给 `allow-same-origin`**。沙箱内的 JS 因此处于唯一源（opaque origin），访问 `parent.localStorage`、`parent.document` 会直接抛 `SecurityError` —— API Key 与全部机器人数据都在 parent 这边，沙箱够不着。

规范说会拦，不等于这台机器的内核真会拦。所以**每次安装前都会实跑一次隔离自检**：在真沙箱里试着摸 `parent.localStorage`，摸得到就拒绝安装。验证放在用户机器上、每次都做。

插件能做的事只有三件，安装前会逐条列出来让你确认：

| 能力 | 约束 |
|---|---|
| 联网 | 只能访问插件自己声明的域名，精确匹配或子域匹配（声明 `example.com` 允许 `api.example.com`，但不会误放 `evilfoo.com`），越界直接回绝而不代发 |
| 声明工具 | 供模型调用或手动试跑 |
| 读取当前对话 | 需插件声明 `readChat`，未声明时传进去的是空数组 |

没有插件独立存储，拿不到 DOM，拿不到主应用数据。

### 两种运行环境的联网差异

| | 桌面版 exe | 浏览器打开 HTML |
|---|---|---|
| 通道 | Python 侧 `bc_http()` 代理（`urllib`，不受同源策略约束） | 页面 `fetch`，Origin 为 `null` |
| 可用接口 | 任意 | 只有返回 `Access-Control-Allow-Origin` 的 |

`examples/plugins/` 下的三个示例正好覆盖两种：`weather` 与 `exchange-rate` 的接口返回 `ACAO: *`，两边都能用；`express-track`（快递 100）不返回跨域头，**只有桌面版能调通**。

Python 侧另有硬约束（不依赖页面侧的白名单）：只放行 http/https、拒绝内网与回环地址、超时 20 秒、响应体上限 2 MB、不转发 `Origin`/`Referer`。

### 怎么装

1. **注册表**：插件中心顶部填一个注册表 JSON 地址，点「拉取」即可浏览安装。`examples/plugins/registry.json` 就是一份自包含的示例（内嵌三个插件），托管到任意静态地址后填进来即可。注册表项也可以只放元数据 + `url`，代码在确认安装时才拉取。
2. **单个链接**：「从链接安装」，粘贴插件 JSON 的地址。
3. **本地文件**：「导入本地文件」，选一个 `.json`。

插件包格式（`.json`）：

```json
{
  "id": "weather", "name": "实时天气", "version": "1.0.0",
  "icon": "🌤️", "category": "数据", "desc": "…", "cap": "…", "author": "…",
  "permissions": { "domains": ["api.open-meteo.com"], "readChat": false },
  "tools": [{ "name": "get_weather", "description": "查询城市天气", "parameters": { "type": "object" } }],
  "code": "plugin.register('get_weather', async function (args, ctx) { … });"
}
```

`id` 只允许 `[a-z0-9][a-z0-9._-]{1,48}`，代码上限 200 KB。沙箱内可用 `plugin.host.fetch(url, opts)` 联网、`plugin.register(name, fn)` 声明工具。

> ⚠️ 插件是外部代码，只装你信得过的来源。装之前看清楚它要访问哪些域名。

## 文件说明
- `BotCraft.html` — 主应用（HTML/CSS/JS 全部内嵌，约 989 KB；其中约 245 KB 是内嵌的等宽字体 base64）。
- `BotCraft.exe` — 桌面版（由 pywebview + PyInstaller 打包，约 14.1 MB），双击即开、无需浏览器；已随仓库分发，需联网调用模型 API。数据写在 `%APPDATA%\BotCraft\data.json`，自动备份在 `%APPDATA%\BotCraft\backups\`。
  - ⚠️ 这份二进制是**发布快照**，不会跟每次源码改动自动同步 —— 只有改到影响桌面版行为（落盘通道、图标、窗口、打包依赖）时才会重新构建。想拿最新桌面版，用下面的 [构建与校验](#构建与校验开发者) 自己打包一份，别假设仓库里的 exe 与最新 `BotCraft.html` 逐字节对应。
- `botcraft.ico` — 项目图标（16/24/32/48/64/128/256 共 7 档），用于桌面快捷方式、窗口与任务栏标识。设计为靛紫渐变底 + 白色扁头 + 两点眼；**16/24px 另用一套简化几何**（去掉天线与信号灯、脸部放大到 67%、眼睛按 16px 网格反推成 2.5px），因为等比缩小会让细线和小弧被降采样抹成灰噪点。
- `gen_icon.py` — 图标生成器：改色或改形状后一条命令即可重生成 `.ico`（同步两份副本）、**就地替换** HTML 里内联的 favicon，并同步界面两处 `.logo .dot` 的内联 SVG（几何的单一来源是 `LOGO_GEOM`，改一处四处一起变）。`python gen_icon.py` 直接改文件，加 `--dry` 只出预览图（浅色/深色两种背景，16→256px 一览）不动文件。

## 快速开始

1. 获取文件：
   - 桌面版（推荐，最省事）：直接双击仓库内的 `BotCraft.exe`（发布快照，重新打包见 [构建与校验](#构建与校验开发者)），无需浏览器、无需起服务，开箱即用；首次运行若被系统拦截，属正常 Windows 安全提示，允许运行即可。数据（机器人 / 知识库 / 账号 / 设置）持久化在 `%APPDATA%\BotCraft\data.json`，关掉应用或清理后台都不会丢；想恢复初始状态，删掉该文件即可。在此之前**先删备份目录** `%APPDATA%\BotCraft\backups\`——否则想彻底重来时，旧数据会跟着备份一起留在这台机器上。误删了东西也别慌：工具条「💾 备份」面板里能一键回滚（见 [数据安全](#数据安全)）。

     ```bash
     # Python
     python -m http.server 8000
     ```

     ```bash
     # Node
     npx serve .
     ```

3. 接入真实大模型：

- 本地配置键：`botcraft.ai.config.v1`（存于 localStorage 或内存回退）。

```json
{
  "provider": "openai",
  "baseURL": "https://api.openai.com/v1",
  "apiKey": "sk-xxxx",
  "model": "gpt-4o-mini",

  "imageAPIKey": "sk-xxxx",

  "imageSize": "1024x1024"
```

- `directCall = true`：浏览器直接请求模型接口（需在浏览器暴露 API Key，不安全）。

## 示例：简单代理（Node.js + Express）
> 演示用途，生产环境请加认证、限流与日志。

```js
const express = require('express');
const fetch = require('node-fetch');
const app = express();
app.use(express.json());
const TARGET = 'https://api.openai.com/v1/chat/completions';

app.post('/api/ai-proxy', async (req, res) => {
  try {
    const OPENAI_KEY = process.env.OPENAI_API_KEY;
    if (!OPENAI_KEY) return res.status(500).json({ error: 'No API key configured' });
    const resp = await fetch(TARGET, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${OPENAI_KEY}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(req.body)
    });
    const data = await resp.text();
    res.status(resp.status).send(data);
  } catch (err) {
    console.error(err);
    res.status(500).json({ error: String(err) });
  }
});

app.listen(3000, () => console.log('Proxy listening on :3000'));
```

部署后在设置中填入代理地址（如 `https://your-domain.com/api/ai-proxy`）并关闭 directCall。

## 安全与隐私提示
- API Key 保存在浏览器 localStorage（或内存回退），不安全用于多用户生产场景。**「导出全部配置」会包含明文 API Key，请勿外传。**
- **自动备份同样是明文 JSON**（内容等于某个时刻的 `data.json`，含 API Key 与全部对话）。别把 `%APPDATA%\BotCraft\backups\` 同步进网盘、共享文件夹或代码仓库。
- 生产建议：用后端代理（如上示例），后端实现认证、审计、限流与 Key 管理。
- 演示账号密码为 PBKDF2-SHA256 本地哈希（仅演示），勿用于真实敏感账号。
- CORS：浏览器直连且 Base URL 不允许跨域时，请改用代理转发。
- 单文件应用无后端，「代码执行器 / PDF 解析」中需外部 API 的部分仅为能力提示或沙盒试运行，无法在本地真正运行。**文生图已可真实执行**：未配置 Key 时回退 pollinations.ai 免费图床，配置了 imageBaseURL + imageAPIKey 后走 OpenAI Images 兼容接口；图片以 data URL 内嵌进聊天，渲染不再依赖浏览器二次外链加载。

## 常见报错排查

### `HTTP 403：Free quota exhausted...` / 错误码 `AllocationQuota.FreeTierOnly`

**这不是 Key 的问题**，重试、换网络、挂代理都不会好。含义是：该账户在这个模型上的**免费额度已用尽**，且服务商开启了「免费额度用完即停」。

以阿里云百炼为例（最常遇到）：

- **成因**：百炼为新用户按模型赠送免费额度（每个模型约 100 万 tokens，有效期约 90 天），并默认对未实名用户强制开启「免费额度用完即停」（也称安心模式）。额度耗尽后直接返回 403，不再继续调用。
- **免费额度与付费余额独立计算**：控制台里显示「还有余额」但依然报 403，是正常现象——它说的是付费余额，不是免费额度。

三种解法，任选其一：

1. **关闭用完即停开关**（想继续用同一个模型）：百炼控制台 → 模型用量 → 免费额度页签 → 找到该模型 → 关闭右侧「免费额度用完即停」开关 → 之后转为按量付费调用。
2. **实名认证 + 充值**：未完成实名认证时该开关由系统强制开启、不可关闭，必须先实名并充值。
3. **换用仍有免费额度的模型**（零成本）：在「设置」里把模型改成 `qwen-plus` / `qwen-turbo` 等，或换一家服务商。

**选型提醒**：`qwen3.8-max` 是 2026-09 上线的旗舰模型，按量单价较高（约 输入 12 元 / 输出 36 元 每百万 tokens），不是刷工作流的合适选择。工作流会逐节点调用模型，用旗舰模型跑长流程很容易在短时间内烧完额度。本应用内置模型列表已把 `qwen-plus` 等均衡型模型排在前列。

### 其他状态码

| 状态码 | 含义 | 处理 |
|---|---|---|
| 401 | Key 无效或已过期 | 在「设置」中重新粘贴密钥 |
| 403（非额度类） | Key 无权访问该模型 / 模型未开通 | 检查密钥权限，确认模型已在控制台开通 |
| 400 | 请求体超出上下文上限 | 换上下文更大的模型，或减少挂载的知识库 |
| 404 | 路径或模型名不存在 | 检查 Base URL 与模型名 |
| 429 | 触发限流或超每分钟额度 | 稍后重试，或降低发送频率 |
| 5xx | 服务端临时故障 | 已自动重试，仍失败则稍后再试 |

### 误删了机器人 / 对话，或数据看起来「退回」了

桌面版每次写盘前都会自动快照一份，所以**大概率能捞回来**：

1. 工具条点「💾 备份」，面板里「🛡️ 本机自动备份」列出最近 12 份 —— **文件名就是拍摄时刻**，按时间挑一份早于出事时点的。
2. 点「恢复」。回滚前当前状态会先被存成一份 `pre-restore`，点错也能退回来；恢复后页面自动重载。
3. 面板顶部会显示备份目录路径，也可以直接去 `%APPDATA%\BotCraft\backups\` 把某份 JSON 复制出来留档。

⚠️ 恢复是**整文件级**的，会把该快照里的全部数据（含账号）一起盖回去 —— 它换的是整个 `data.json`，不是单个机器人。因此建议动手前先点一次「🛡️ 立即备份」，给当前状态留个底。

## 已知限制
- 单文件结构便于演示但不利于长期维护。
- 无后端持久化，数据均保存在本地；换浏览器 / 换 origin / 清缓存会读不到，需用「💾 备份」导出导入迁移。**桌面版更稳**：启动时把已落盘数据注入页面、运行中经桥接写回 `%APPDATA%\BotCraft\data.json`，不依赖浏览器存储（部分环境下 WebView2 并不会把 localStorage 落盘），因此关掉应用 / 清理后台后数据仍在。**自动备份与一键回滚同样只在桌面版可用**——它们依赖这条落盘通道，浏览器版请用「导出全部配置」做人工备份。
- 自动备份有 10 分钟限频、只留 12 份：**它是防损坏 / 防误删的兜底，不是版本控制系统**。要长期留档请用「导出全部配置」或机器人级的版本快照。
- 本地存储不是无限的：**单个会话保留最近 100 条消息、每个机器人保留最近 30 个版本快照**，超出后自动淘汰最早的（另：Token 用量按天聚合只留 60 天，长期记忆容量 60 条）。要留证据请及时「导出 Markdown」或导出配置。
- 「🧹 清理内联媒体」与「⚠️ 应急恢复」都**不可撤销**：前者把语音 / 配图换成文字占位（消息文字与结构保留，但**原图原音频取不回来**），后者清空全部数据。清理前建议先点一次「🛡️ 立即备份」；应急恢复会自动留一份 `pre-emergency` 备份，但它同时也会清掉账号，需要重新注册 / 登录。
- CORS 与浏览器安全策略会限制部分模型直连。
- 部分 UI 文案含 emoji，个别场景显示依赖系统字体。
